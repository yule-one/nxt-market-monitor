# 로그인·사용자 관리 안내

## 적용 방식

- 공개 회원가입은 제공하지 않습니다.
- 앱 최초 실행 시 관리자 계정을 한 번 생성합니다.
- 관리자가 사용자 계정과 임시 비밀번호를 발급합니다.
- 임시 비밀번호를 받은 사용자는 첫 로그인 직후 새 비밀번호로 변경해야 합니다.
- 관리자만 사용자 목록, 권한, 활성 상태, 잠금, 비밀번호 초기화와 관리 기록을 볼 수 있습니다.
- 모든 사용자는 `내 계정`에서 본인 비밀번호를 변경할 수 있습니다.

## 최초 설정

1. 로컬에서 `streamlit run app.py`를 실행합니다.
2. `초기 관리자 설정` 화면에서 관리자 아이디, 표시 이름과 비밀번호를 입력합니다.
3. 관리자 로그인 후 사이드바의 `사용자 관리`에서 부서원 계정을 발급합니다.
4. 임시 비밀번호는 별도의 안전한 수단으로 사용자에게 전달합니다.

외부에서 접근 가능한 환경에서 초기 설정 화면을 사용할 경우 `.streamlit/secrets.toml`에 다음 값을 먼저 설정합니다.

```toml
AUTH_SETUP_TOKEN = "충분히-길고-임의적인-초기설정-토큰"
```

`AUTH_SETUP_TOKEN`은 관리자 비밀번호가 아니며, 첫 관리자 생성 화면을 보호하기 위한 값입니다. 첫 관리자 생성이 끝나면 설정 화면은 다시 나타나지 않습니다.

## 계정 운영

### 계정 발급

`사용자 관리 → 계정 발급`에서 아이디, 표시 이름, 권한과 임시 비밀번호를 입력합니다. 아이디는 영문 소문자, 숫자, 마침표, 밑줄과 하이픈을 사용해 3~32자로 만듭니다.

### 비밀번호

- 10~128자
- 영문자와 숫자를 각각 하나 이상 포함
- PBKDF2-HMAC-SHA256 600,000회와 계정별 임의 salt로 해시해 저장
- 원문 비밀번호는 데이터베이스와 감사기록에 저장하지 않음

관리자가 비밀번호를 초기화하면 해당 사용자는 다음 화면 이동 전에 다시 비밀번호를 변경해야 합니다.

### 로그인 잠금

비밀번호를 5회 연속 잘못 입력하면 15분 동안 로그인할 수 없습니다. 관리자는 `사용자 관리 → 계정 설정 → 로그인 잠금 해제`로 즉시 해제할 수 있습니다.

### 권한과 비활성화

- `일반 사용자`: 대시보드 조회와 본인 비밀번호 변경
- `관리자`: 일반 사용자 기능과 계정 발급·관리·감사기록 조회
- 현재 로그인한 관리자는 자기 계정을 비활성화할 수 없습니다.
- 마지막 활성 관리자 계정은 비활성화하거나 일반 사용자로 변경할 수 없습니다.
- 계정은 삭제하지 않고 비활성화해 감사 이력을 보존합니다.

## 저장 위치

앱은 다음 우선순위로 계정 저장소를 선택합니다.

1. `AUTH_DATABASE_URL`이 있으면 PostgreSQL
2. 값이 없으면 로컬 `data/auth.db` SQLite

PostgreSQL 연결이 설정됐는데 접속에 실패하면 SQLite로 자동 전환하지 않습니다. 잘못된 DB에 새 계정이 만들어지는 것을 막기 위해 로그인 화면 대신 연결 오류를 표시합니다.

로컬 `auth.db`는 `.gitignore`에 의해 Git에 포함되지 않습니다. 로컬 PC를 교체하거나 디스크 장애에 대비하려면 앱을 종료한 상태에서 파일을 암호화된 사내 저장소에 백업해야 합니다.

브라우저 로그인 상태는 Streamlit 세션에만 보관합니다. 브라우저 세션이나 앱 프로세스가 종료되면 다시 로그인해야 합니다.

## PostgreSQL 설정

관리형 PostgreSQL에서 데이터베이스와 전용 사용자를 만든 뒤 `.streamlit/secrets.toml`에 다음 값을 추가합니다.

```toml
AUTH_DATABASE_URL = "postgresql://사용자:비밀번호@호스트:5432/DB이름?sslmode=require"
AUTH_SETUP_TOKEN = "충분히-길고-임의적인-초기설정-토큰"
```

실제 접속주소와 비밀번호는 GitHub에 올리지 않습니다. 로컬에서는 무시되는 `.streamlit/secrets.toml`에, Streamlit Community Cloud에서는 앱 설정의 Secrets에 저장합니다.

앱이 처음 연결될 때 다음 테이블을 자동 생성합니다.

- `app_users`: 아이디, 표시 이름, 비밀번호 해시, 권한, 활성·잠금 상태
- `auth_audit_log`: 로그인과 계정관리 감사기록

DB 관리자에게 사전 검토를 받아야 한다면 [PostgreSQL 스키마](../scripts/sql/auth_postgresql.sql)를 전달할 수 있습니다.

연결만 확인하려면 다음 명령을 실행합니다.

```powershell
python scripts\migrate_auth_to_postgres.py --check-only
```

`PostgreSQL 연결 성공 · 대상 상태: 비어 있음`이 표시되면 준비된 것입니다.

## 기존 SQLite 계정 이전

기존 `data/auth.db`에 발급한 계정이 있으면 앱을 중지한 상태에서 다음 명령을 한 번 실행합니다.

```powershell
python scripts\migrate_auth_to_postgres.py
```

비밀번호 원문은 복호화하거나 다시 만들지 않습니다. 기존 PBKDF2 비밀번호 해시, 계정 상태와 관리기록을 그대로 옮기므로 사용자는 기존 비밀번호로 로그인할 수 있습니다.

안전상 대상 PostgreSQL에 계정이나 관리기록이 하나라도 있으면 이전을 중단합니다. 중복 실행이나 기존 운영계정 덮어쓰기를 허용하지 않습니다.

## 배포 전 확인사항

이번 변경은 배포하지 않습니다. 향후 Streamlit Community Cloud에 배포할 때는 다음을 확인합니다.

1. `AUTH_DATABASE_URL`과 `AUTH_SETUP_TOKEN`을 Cloud Secrets에 저장
2. PostgreSQL의 SSL 연결, 백업과 접속 허용 범위 확인
3. `--check-only`로 연결 확인 후 빈 DB라면 초기 관리자를 생성하거나 기존 계정을 이전
4. 관리자·일반 사용자 로그인, 비밀번호 변경, 계정 비활성화 테스트
5. 시세정보 이용계약상 내부 화면 표출 인원과 저장 범위 확인
