# 로그인·회원관리 안내

## 계정 이용 흐름

1. 사용자가 로그인 화면의 `회원가입 신청` 탭에서 아이디, 비밀번호, 사번, 이름을 입력합니다.
2. 신청 계정은 PostgreSQL의 `승인 대기` 상태로 저장되며 아직 로그인할 수 없습니다.
3. 관리자가 `사용자 관리 > 가입 승인`에서 사번과 이름을 확인해 승인하거나 반려합니다.
4. 승인된 사용자는 본인이 정한 아이디와 비밀번호로 로그인합니다.
5. 반려된 사용자는 올바른 비밀번호로 로그인할 때 반려 상태와 관리자가 입력한 사유를 확인할 수 있습니다.

회원가입 신청은 항상 일반 사용자 권한으로 생성됩니다. 관리자 권한은 승인 후 기존 `계정 설정` 화면에서 별도로 부여해야 합니다.

## 최초 관리자 설정

계정 DB가 비어 있을 때만 `초기 관리자 설정` 화면이 표시됩니다. 이 화면에서 최초 관리자 한 명을 만든 뒤 회원가입 신청과 승인을 운영합니다.

외부에서 접근할 수 있는 환경에서는 `.streamlit/secrets.toml` 또는 Streamlit Community Cloud Secrets에 초기 설정 토큰을 반드시 설정합니다.

```toml
AUTH_SETUP_TOKEN = "충분히-길고-임의적인-초기설정-토큰"
```

`AUTH_SETUP_TOKEN`은 관리자 비밀번호가 아니라 빈 계정 DB에 첫 관리자를 만드는 화면을 보호하는 값입니다. 계정이 하나라도 생성되면 초기 설정 화면은 더 이상 표시되지 않습니다.

## 회원가입 신청과 승인

- 아이디: 영문 소문자, 숫자, 마침표, 밑줄, 하이픈을 사용한 3~32자
- 사번: 숫자 6자리
- 이름: 1~50자
- 비밀번호: 10~128자이며 영문자와 숫자를 각각 하나 이상 포함
- 아이디와 사번은 각각 중복될 수 없음
- 사번과 이름은 가입 승인 및 계정 관리 목적으로 인증 DB에 저장

승인 대기 또는 반려 계정은 비활성 상태이며 대시보드에 접근할 수 없습니다. 승인 시 계정이 활성화되고, 사용자가 가입할 때 정한 비밀번호를 그대로 사용합니다. 반려 사유는 선택 입력이며 신청자가 올바른 비밀번호로 상태를 확인할 때만 표시됩니다.

## 관리자 기능

- `가입 승인`: 승인 대기 신청의 사번·이름 확인, 승인 또는 반려
- `반려 계정 삭제`: 반려 계정을 확인 후 삭제하여 같은 아이디와 사번으로 재신청 허용
- `계정 발급`: 관리자가 임시 비밀번호로 계정을 직접 생성
- `계정 설정`: 승인된 계정의 권한, 활성 상태, 로그인 잠금, 비밀번호 초기화 관리
- `관리 기록`: 로그인, 가입 신청, 승인·반려, 계정관리 작업의 감사기록 조회

관리자가 직접 발급하거나 비밀번호를 초기화한 계정은 다음 로그인 직후 비밀번호를 변경해야 합니다. 현재 로그인한 관리자 자신과 마지막 활성 관리자는 비활성화하거나 일반 사용자로 변경할 수 없습니다.

반려 계정은 관리자만 삭제할 수 있습니다. 승인 대기 또는 승인 완료 계정은 이 기능으로 삭제할 수 없으며, 삭제 후에도 기존 가입 신청·반려 및 삭제 감사기록은 보존됩니다. 계정 행이 삭제되므로 해당 아이디와 사번은 다시 회원가입에 사용할 수 있습니다.

## 비밀번호와 로그인 보호

- PBKDF2-HMAC-SHA256 600,000회와 계정별 임의 salt로 비밀번호 해시 저장
- 원문 비밀번호는 데이터베이스와 감사기록에 저장하지 않음
- 비밀번호 5회 연속 오류 시 15분간 로그인 잠금
- 관리자 화면에서 잠금 즉시 해제 가능
- 로그인 성공 시 12시간 유효한 임의 세션 토큰을 발급해 새로고침 후에도 로그인 유지
- 브라우저에는 계정정보가 없는 임의 토큰만 저장하고, PostgreSQL에는 토큰의 SHA-256 해시만 저장
- 로그아웃, 계정 비활성화, 비밀번호 초기화 또는 만료 시 해당 세션 토큰 무효화

승인 상태는 올바른 비밀번호가 확인된 경우에만 로그인 화면에 표시합니다. 아이디가 없거나 비밀번호가 틀린 경우에는 동일한 오류 문구를 사용합니다.

## PostgreSQL 설정

관리형 PostgreSQL에서 데이터베이스와 전용 사용자를 만든 뒤 Secrets에 접속 주소를 저장합니다.

```toml
AUTH_DATABASE_URL = "postgresql://사용자:비밀번호@호스트:5432/DB이름?sslmode=require"
AUTH_SETUP_TOKEN = "충분히-길고-임의적인-초기설정-토큰"
```

실제 접속 주소와 비밀번호는 GitHub에 올리지 않습니다. 로컬에서는 Git에서 제외된 `.streamlit/secrets.toml`, Streamlit Community Cloud에서는 앱 설정의 Secrets에 저장합니다.

앱 시작 시 다음 테이블과 회원가입용 열을 자동으로 생성·보강합니다.

- `app_users`: 아이디, 이름, 사번, 비밀번호 해시, 권한, 승인·활성·잠금 상태
- `auth_sessions`: 로그인 유지용 토큰 해시, 사용자, 발급·만료·최근 확인 시각
- `auth_audit_log`: 로그인과 가입 승인 및 계정관리 감사기록

기존 계정 DB에 회원가입 열이 없으면 자동으로 추가하며, 기존 계정은 모두 `승인 완료`로 이관합니다. DB 관리자가 사전 적용할 SQL은 [PostgreSQL 스키마](../scripts/sql/auth_postgresql.sql)를 사용합니다.

연결 확인:

```powershell
python scripts\migrate_auth_to_postgres.py --check-only
```

기존 로컬 SQLite 계정을 PostgreSQL로 옮길 때는 앱을 중지한 상태에서 다음 명령을 한 번 실행합니다.

```powershell
python scripts\migrate_auth_to_postgres.py
```

## 저장소와 개인정보 운영

`AUTH_DATABASE_URL`이 있으면 PostgreSQL을 사용하고, 없으면 로컬 개발용 `data/auth.db` SQLite를 사용합니다. PostgreSQL 연결 실패 시 SQLite로 자동 전환하지 않습니다.

사번과 이름은 인증 DB에 평문으로 저장되므로 DB 접근 권한을 관리자와 앱 서비스 계정으로 제한하고, PostgreSQL 전송 암호화(SSL), 백업 암호화, 보존·삭제 기준을 사내 정책에 맞게 운영해야 합니다. 비밀번호와 사번을 로그나 오류 메시지에 남기지 않습니다.
